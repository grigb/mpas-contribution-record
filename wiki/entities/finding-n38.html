The release procedure promoted alpha builds to the stable tag

Following the documented release steps published a prerelease and then pointed latest at it, so anyone installing the stable library could receive an alpha

What was wrong

sdk/protocol/RELEASING.md instructed npm publish --access public --tag alpha and, on the very next line, npm dist-tag add @oma3/mpas@0.1.0-alpha.N latest. The closing sentence that stable releases use latest contradicted that command, and no test exercised tag selection. The file is unchanged from the patch base to main.1

Why it matters

Users who install without naming a tag get whatever latest points at.

The fix

The promotion line is deleted and replaced by a dist-tag rule: a prerelease is always published under its channel tag and never given latest, at publish time or by a later dist-tag add; npm publish --dry-run --tag <tag> confirms the selection without publishing. A new sdk/protocol/tests/lib/release-tag-selection.test.ts (154 lines, 6 tests) derives the tag from a version string, checks the document for any promotion line, and dry-runs npm. RELEASING.md changes 11 lines. Package 13, commit 3d15071: 15 files, 1,323 insertions, 38 deletions shared with N39, N40, N43 and issues 18, 25 and 63.
